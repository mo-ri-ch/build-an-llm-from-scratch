Embeddings

The problem

My three tables work. But they explode when there are more letters.

Right now your model has 588 numbers: 3 tables × 14 letters × 14 next letters. With 1,000 letters it would need 3 million, and with all of Unicode, 67.5 billion.

Every letter has a row in each of the 3 tables (third-last, second-last, last). So “a” has 3 rows, learned separately.

Instead of 3 big rows for “a”, could “a” have just 2 numbers, used everywhere?

What would 2 numbers for a letter look like?

A letter as numbers

Give every letter 2 numbers, like a = [0.68, −1.23]. All 14 letters share one table, with one row each. This table is the embedding table. Each row is a letter's embedding: its 2 embedding numbers.

🤔 How can 2 numbers replace 14 scores?

They don't hold the scores. They say what kind of letter this is. The next page turns them into 14 scores, using weights shared by every letter. So the model needs far fewer numbers.

The price: a slightly higher loss (0.178 against 0.174).

The numbers start random, like every number your model starts with.

Pick a group. Its 3 letters pick 3 rows from the one table.
Your model reads the 3 letters as 6 embedding numbers:

“a” has the same 2 numbers in “cat”, “sat” and “mat”, wherever it sits. One row to learn, not three.

6 embedding numbers. How do they become a guess?

Numbers to a guess

For every letter that could come next, there are 6 weights, one for each of the 6 embedding numbers. To score one possible next letter, like space: multiply each embedding number by its weight, then add.

The 6 embedding numbers come from the 3 letters you read (2 each). The possible next letters have no embedding numbers, only weights.

There are 6 × 14 = 84 weights (hover to see them), random at the start too.

Of each letter's 6 weights, the 1st and 2nd go with the third-last letter, the 3rd and 4th with the second-last, the 5th and 6th with the last. That is how the model knows which letter is where.

Pick a group and a next letter. Watch its score being built.
Your model does this for all 14 next letters. Softmax turns the 14 scores into chances.

Your model now has 28 embedding numbers + 84 weights = 112 numbers, instead of 588.

Can numbers this few still learn? Learning has to reach the letters too.

Here's all of it in Python.

The code

Guess what each print shows. Then press ▶ Run.

import torch
import torch.nn.functional as F

text = "the cat sat on the mat. the dog sat on the log."
unique_chars = sorted(set(text))
vocab_size = len(unique_chars)
char_to_number = {}
number_to_char = {}
for number, char in enumerate(unique_chars):
    char_to_number[char] = number
    number_to_char[number] = char

# Examples: the last 3 letters, and the next one
third_last = []
second_last = []
last = []
next_chars = []
for i in range(len(text) - 3):
    third_last.append(char_to_number[text[i]])
    second_last.append(char_to_number[text[i + 1]])
    last.append(char_to_number[text[i + 2]])
    next_chars.append(char_to_number[text[i + 3]])
third_last = torch.tensor(third_last)
second_last = torch.tensor(second_last)
last = torch.tensor(last)
next_chars = torch.tensor(next_chars)
print("Examples:", len(next_chars))

# The model: 2 embedding numbers per letter, 6 weights per next letter
torch.manual_seed(42)
embedding = torch.randn((vocab_size, 2), requires_grad=True)
weights = torch.randn((6, vocab_size), requires_grad=True)
print("Numbers in the model:", embedding.numel() + weights.numel())

# Learn: predict, measure, find directions, move
learning_rate = 1
for step in range(300):
    numbers = torch.cat([embedding[third_last], embedding[second_last], embedding[last]], dim=1)   # a) the 6 embedding numbers of every example
    scores = numbers @ weights                                                                     # multiply by the weights, add up
    loss = F.cross_entropy(scores, next_chars)                                                     # b) measure
    embedding.grad = None
    weights.grad = None
    loss.backward()                                                                                # c) find directions
    embedding.data = embedding.data - learning_rate * embedding.grad                               # d) move
    weights.data = weights.data - learning_rate * weights.grad
    if step % 50 == 0:
        print("Step", step, "loss:", round(loss.item(), 3))

# Write 40 new letters, starting from "the"
torch.manual_seed(42)
output = "the"
for step in range(40):
    numbers = torch.cat([embedding[char_to_number[output[-3]]], embedding[char_to_number[output[-2]]], embedding[char_to_number[output[-1]]]])
    scores = numbers @ weights
    chances = F.softmax(scores, dim=0)
    picked = torch.multinomial(chances, num_samples=1).item()
    output = output + number_to_char[picked]
print(output)

🤔 What is new in this code?
  • embedding is the embedding table: a row of 2 embedding numbers for every letter. weights is 6 rows, one weight for each of the 6 embedding numbers, for every next letter.
  • torch.cat([...], dim=1) puts the 3 letters' numbers side by side: 6 embedding numbers for each example.
  • numbers @ weights multiplies each embedding number by its weight and adds, for every next letter at once.
  • The learning rate is 1 this time: 10 is too big for these numbers.

What your model still can't do.

Each letter votes alone

Each letter has one embedding (its 2 numbers), used in every position. That is why the model needs only 112 numbers. But it also means “a” has the same 2 numbers after “c” as after “s”: its neighbours never change them.

Each letter adds its own part to a score: its embedding × the weights for its place. Change one letter: which parts change?

In “cat”, “a” has the same embedding as in “sat” and “mat”. It never looks at the letters around it.

I only need 112 numbers! But each letter still votes alone.
