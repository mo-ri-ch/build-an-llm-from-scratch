Let the model learn

In Lesson 3 we counted which character comes after which. In this lesson the model starts knowing nothing and learns the same thing by itself, by fixing its own mistakes.

Part 1 of 6

The problem

Lesson 3 ended with this question: counting only works for a tiny table. Can a model learn the probabilities by itself instead?

Counting worked because our model looks at just 1 previous character, so the table has one row per character. But a good model needs to look further back, and the number of rows explodes:

Looks back atRows to count
1 character14
3 characters2,744
10 characters289,254,654,976

Most of those combinations never appear in the text, so there's nothing to count. We need a different method: start with random numbers and improve them until the predictions are good. That method works for any model, of any size. GPT is trained this way too.

This lesson gets the same answer as counting, on purpose. We test the new method where we already know the right answer.

Part 2 of 6

The idea

The model is a 14 × 14 table, just like Lesson 3's. One row for each current character, one column for each possible next character. But instead of counts, it holds scores, and they start random.

Then we repeat four steps:

  1. a)Predict. Use the scores to guess the next character for every pair in the text.
  2. b)Measure. Work out one number that says how wrong the guesses are. This is the loss.
  3. c)Find directions. For every score, work out: should it go up or down to make the loss smaller? These are the gradients.
  4. d)Move. Nudge every score a little in its direction.
  5. ↺Repeat 300 times.

Part 4 of 6

One step, slowly

Here is exactly what happens in the very first step, with the real numbers. Press Next to go on.

a) Predict

scores = weights[current_chars]

current_chars holds the 46 characters of the text that have a character after them: [13, 7, 5, 0, 3, …], which means t, h, e, space, c…

For each of those 46 numbers, PyTorch copies that whole row from weights. Row 13 is the t row, so the first copy is:

        ' '     '.'     'a'  …   'h'     'l'   …
t row: [0.4788, 1.3537, -0.1593, … 1.0687, 1.3065, …]

Result: scores is 46 rows × 14 scores. One row of guesses for every pair.

The correct answer after t here is h (1.0687), but '.' (1.3537) and l (1.3065) score higher. The scores are random, so the guesses are bad.

Still unclear? How can one line copy 46 rows?

Tensors allow a list of positions inside the brackets. You get back all those rows, in that order. The same row can appear more than once.

table = torch.tensor([[10, 11],    # row 0
                      [20, 21],    # row 1
                      [30, 31]])   # row 2

print(table[torch.tensor([2, 0, 2])])
# tensor([[30, 31],
#         [10, 11],
#         [30, 31]])

A normal Python list can't do this. It's a tensor feature.

b) Measure

loss = F.cross_entropy(scores, next_chars)
# 3.0865

cross_entropy does four things:

  1. Softmax each row: turn the 14 scores into 14 probabilities that add up to 1.
  2. Pick the probability of the correct answer. next_chars says which one is correct.
  3. Take −log of it. That's the loss for that one pair.
  4. Average all 46 losses into one number.
PairCorrect nextProbability given−log
t → ?h0.13302.0178
h → ?e0.02813.5732
e → ?space0.02403.7277
… 43 more pairs …
Average of all 463.0865

Why −log? It turns “how much probability did the right answer get” into “how wrong”, where 0 is perfect:

Probability of the right answer−logMeaning
1.00.00perfect
0.50.69okay
0.12.30bad
0.014.61very bad
Still unclear? What does softmax do?

Scores can be negative or bigger than 1, so they can't be probabilities yet. Softmax fixes that in two steps:

  1. Make every number positive with ex. Bigger score, bigger result.
  2. Divide each by the total, so they add up to 1.
scores        = [2.0, 1.0, -1.0]
e^score       = [7.389, 2.718, 0.368]     # total 10.475
probabilities = [0.705, 0.259, 0.035]     # each ÷ 10.475

The highest score still gets the highest probability. It's like Lesson 3's “divide by the row total”, with ex first so negative scores work.

c) Find directions

weights.grad = None
loss.backward()

We have one number, the loss, and we want it smaller. The only thing we can change is the 196 scores. For each score there are only two choices: up or down. Which one makes the loss smaller?

Try it yourself. Change one score by a tiny amount and watch the loss:

Press a button.

That's what loss.backward() works out, for all 196 scores at once. It stores the answers in weights.grad, a second 14 × 14 table:

weightsthe scores (the model)
t row, h: 1.0687
weights.gradthe directions
t row, h: −0.0638

Each gradient answers: “if this score goes up, what happens to the loss?”

  • Negative: the loss goes down. Good, so we'll raise the score.
  • Positive: the loss goes up. Bad, so we'll lower the score.

weights.grad = None clears the old directions first, because PyTorch adds new gradients on top of old ones.

Still unclear? How does backward() reach weights.grad?

Because weights has requires_grad=True, every result made from it remembers where it came from:

loss  ←  cross_entropy  ←  scores  ←  pick rows  ←  weights

loss.backward() starts at loss, follows that chain backwards, works out the gradients along the way, and writes them into weights.grad. Without requires_grad=True there's no chain, and backward() gives an error.

Still unclear? Show me the exact math for one score.

Take the h score in the t row. The probability of h after t is 0.1330.

  1. Only pairs that start with t use this row. There are 8: t→h, t→space, t→space, t→h, t→., t→h, t→space, t→h.
  2. For each pair, one rule: if h is the correct answer, 0.1330 − 1. If not, 0.1330.
  3. Add them: 4 × (−0.8670) + 4 × 0.1330 = −2.9360
  4. Divide by 46, because the loss was an average: −0.0638

Why “− 1”? A perfect probability for the right answer is 1. So probability − 1 is how far it is from perfect. Far from perfect means a big push.

d) Move

weights.data = weights.data - learning_rate * weights.grad

New score = old score − learning rate × gradient. Our learning rate is 10, the size of each step.

h:  1.0687 − 10 × (−0.0638) = 1.0687 + 0.638 = 1.7070   # went up
l:  1.3065 − 10 × (+0.0293) = 1.3065 − 0.293 = 1.0135   # went down

The minus sign does the flipping: minus a negative gradient moves the score up, minus a positive one moves it down.

h really comes after t, and its score went up. l never does, and its score went down. That's learning.

Then repeat

The next step starts from the new scores, so its guesses are a little better. After one step the loss went from 3.0865 to 2.5462. After 300:

Part 5 of 6

The code

The complete lesson4.py. The outputs are shown as comments, so you can check yours match. Run it with python lesson4.py.

import torch
import torch.nn.functional as F

# ---------- Step 1: Our training text ----------
text = "the cat sat on the mat. the dog sat on the log."


# ---------- Step 2: Give each character a number ----------
unique_chars = sorted(set(text))
vocab_size = len(unique_chars)

char_to_number = {}
number_to_char = {}
for number, char in enumerate(unique_chars):
    char_to_number[char] = number
    number_to_char[number] = char

print("Vocabulary size:", vocab_size)
# Vocabulary size: 14


# ---------- Step 3: Make training pairs ----------
current_chars = []
next_chars = []
for i in range(len(text) - 1):
    current_chars.append(char_to_number[text[i]])
    next_chars.append(char_to_number[text[i + 1]])

current_chars = torch.tensor(current_chars)
next_chars = torch.tensor(next_chars)

print("Number of training pairs:", len(current_chars))
# Number of training pairs: 46


# ---------- Step 4: Create the model ----------
torch.manual_seed(42)
weights = torch.randn((vocab_size, vocab_size), requires_grad=True)

print("Row for 't':", weights[13])
# Row for 't': tensor([ 0.4788,  1.3537, -0.1593, -0.4249,  0.9442, -0.1849,  0.1852,
#                       1.0687,  1.3065,  0.4598,  0.2618, -0.7599, -2.0461, -1.5295])


# ---------- Step 5: Train the model ----------
learning_rate = 10
number_of_steps = 300

for step in range(number_of_steps):

    # a) Predict
    scores = weights[current_chars]

    # b) Measure how wrong
    loss = F.cross_entropy(scores, next_chars)

    # c) Find directions
    weights.grad = None
    loss.backward()

    # d) Move
    weights.data = weights.data - learning_rate * weights.grad

    if step % 50 == 0:
        print("Step", step, "loss:", round(loss.item(), 3))

# Step 0 loss: 3.086
# Step 50 loss: 0.746
# Step 100 loss: 0.722
# Step 150 loss: 0.714
# Step 200 loss: 0.711
# Step 250 loss: 0.709


# ---------- Step 6: See what the model learned ----------
probabilities = F.softmax(weights, dim=1)

t_number = char_to_number['t']
t_row = probabilities[t_number]

print("After 't':")
for number in range(vocab_size):
    probability = t_row[number].item()
    if probability > 0.01:
        print("  ", repr(number_to_char[number]), round(probability, 3))

# After 't':
#    ' ' 0.374
#    '.' 0.124
#    'h' 0.499

Part 6 of 6

Check yourself

Guess first, then reveal the answer.

A score's gradient is +0.0090. Will step d) move that score up or down?
Down. Positive means “raising this score makes the loss bigger”, so we lower it. In the formula: score − 10 × 0.0090 = score − 0.09.
What happens if we remove requires_grad=True?
loss.backward() gives an error. PyTorch didn't record how the loss was made from the weights, so it can't work out any gradients, and the model can't learn.
What goes wrong if we delete the line weights.grad = None?
PyTorch adds new gradients on top of old ones. Without clearing, every step would use the sum of all past gradients, and the moves would get bigger and wronger.
After training, the model gives h 0.499 after t. Counting gave 0.500. So why learn at all, if counting gives the same answer?
Counting only works while the table is small. Learning works for any model of any size, as long as it produces a loss. We tested it here, where we know the right answer, so we can trust it later where counting is impossible.
