Learning (this lesson)

Start with random numbers. Guess, see how wrong, fix them a little. Repeat many times.

Works for any numbers, even ones that can't be counted.

🤔 Isn't this more work than counting?

Yes. Counting reads the text once. Learning goes through all 46 pairs, fixes every score a little, and repeats that 300 times.

For this small table, counting is quicker. But the smarter model in Lesson 5 has numbers that can't be counted, and learning still works there.

Here we can check it: learning ends with the same chances as counting.

Learning repeats 4 steps:

  1. a)Predict the next character
  2. b)Measure how wrong
  3. c)Find which way to change each score
  4. d)Move each score a little

To predict, your model needs chances, not scores. How do scores become chances?

Scores into chances

Step a) Predict

To guess, your model needs chances that add up to 1, like Lesson 3's rows.

Any scores in, chances out. They always add up to 1, and raising one score takes chance away from the others.

This is softmax.

The less chance your model gives the right answer, the bigger the loss. Give it 100% and the loss is 0.

The rule your model uses: loss = −log(chance)

🤔 What is log?

You don't need the math. −log just turns a chance into a “how wrong” number:

100% → 0 (perfect), 90% → 0.11, 50% → 0.69, 13.3% → 2.02, 1% → 4.61.

The smaller the chance, the bigger the number.

That was just one pair. Every pair has its own right answer: in “cat ”, t is followed by a space, so there the right answer is space.

Which way?

Steps c) Find directions and d) Move

Take the pair t → h again.

Your model gave h only 13.3%, but the text says h is the right answer. To make the loss smaller, h needs a bigger chance.

The chances come from the scores in row t (softmax: a higher score gives a higher chance). So we change the scores:

  • h's score goes up, so h's chance grows.
  • Every other letter's score goes down, so their chances shrink. The chances always add up to 100%, so what they lose goes to h.

For each score, one number tells us which way to move it, and by how much. That number is its gradient:

  • h (the right answer): gradient = its chance − 1 = 0.133 − 1 = −0.867. (13.3% is written as 0.133.)
  • Every wrong letter: gradient = its chance. For “.”: +0.177.

To move a score: new score = old score − gradient.

  • h: 1.07 − (−0.867) = 1.94. Taking away a negative number adds it, so h's score goes up.
  • “.”: 1.35 − 0.177 = 1.17. A positive gradient makes the score go down.

So the + or − tells the direction, and the distance from 0 tells how much: h (−0.867, far from 0) moves a lot, space (+0.074, close to 0) hardly moves.

🤔 Why “chance − 1” for the right answer?

“1” means 100%, a sure guess. So “chance − 1” is how far the right answer is from 100%.

If your model already gave h 100%: 1 − 1 = 0. Nothing to fix, so the score doesn't move.

It gave only 13.3%: 0.133 − 1 = −0.867. Far from 100%, so the score moves up a lot.

Press “Move a little”. Every score moves by the rule above. Watch h's chance grow and the loss shrink.

In code, one line finds all 196 gradients at once: loss.backward(). You'll see it on the code page.

Here's all of it in Python.

The code

Guess what each print shows. Then press ▶ Run.

import torch
import torch.nn.functional as F

text = "the cat sat on the mat. the dog sat on the log."
unique_chars = sorted(set(text))
vocab_size = len(unique_chars)
char_to_number = {}
number_to_char = {}
for number, char in enumerate(unique_chars):
    char_to_number[char] = number
    number_to_char[number] = char

# Pairs: this character, and the next one
current_chars = []
next_chars = []
for i in range(len(text) - 1):
    current_chars.append(char_to_number[text[i]])
    next_chars.append(char_to_number[text[i + 1]])
current_chars = torch.tensor(current_chars)
next_chars = torch.tensor(next_chars)

# The model: random scores. requires_grad=True lets PyTorch find gradients.
torch.manual_seed(42)
weights = torch.randn((vocab_size, vocab_size), requires_grad=True)

learning_rate = 10
for step in range(300):
    scores = weights[current_chars]                # a) predict
    loss = F.cross_entropy(scores, next_chars)     # b) measure
    weights.grad = None
    loss.backward()                                # c) find directions
    weights.data = weights.data - learning_rate * weights.grad   # d) move
    if step % 50 == 0:
        print("Step", step, "loss:", round(loss.item(), 3))

# What did it learn after 't'?
probabilities = F.softmax(weights, dim=1)
t_row = probabilities[char_to_number['t']]
for char in [' ', '.', 'h']:
    print(repr(char), round(t_row[char_to_number[char]].item(), 3))

🤔 What does each line in the training loop do?
  • weights[current_chars]: copies the row of each of the 46 characters.
  • F.cross_entropy: softmax, pick the right answer's chance, −log, average.
  • weights.grad = None: clears old gradients. PyTorch adds new ones on top.
  • loss.backward(): fills weights.grad with a gradient for every score.
  • weights.data - learning_rate * weights.grad: the minus flips the sign, so negative goes up.
