Attention

The problem

I only see the last 3 letters, “at␣”, so I can't tell if I just wrote “cat” or “sat”. That's why I write “sat sat”.

Your model reads only the last 3 letters. After “cat␣” and after “sat␣” it sees the same 3 letters, “at␣”. But the next letter is different: “cat sat” and “sat on”.

To tell them apart, it must look further back. The model from before would need 28 more weights for every extra letter: its 2 embedding numbers each need a weight for each of the 14 next letters. And each letter would still vote alone.

“at␣” comes 3 times in our text. Each time, the model sees the yellow letters and must guess the blue one. Slide to let it see more letters.

If it could see that the word was “sat”, it would write “on”, never “sat sat”. Could the model look back and pick out the letters that help, like the “c” or “s” before “at␣”?

First, a way to compare two lists of numbers.

✏️ Quick basics: the dot product

You already did this when making a score: multiply two lists' numbers in pairs, then add. This is called the dot product.

It also says how alike two lists are. Draw each list as an arrow. Same direction: big and positive. At a right angle: 0. Opposite: negative.

Keep the first list. Pick the second and watch the arrows and the dot product.

The next pages use it to measure how well two letters fit together.

Now each letter gets numbers to compare.

Letters in a row

Your model now reads the last 8 letters. Think of them as sitting in a row of 8 places, which we call seats: seat 1 holds the oldest letter, seat 8 the newest.

🤔 Why 3 numbers, and what do they mean?

We choose how many: 3 here, 2 before. They still start random. With 2, this model learned badly: the same few numbers must say which letter it is, which seat it sits in, and do the jobs the next pages give them. 3 gives just enough room.

No single number means one thing. Learning moves them to whatever helps the guesses, so together they are a description that only the model uses.

Each letter brings its embedding: 3 numbers, always the same for that letter.

Each seat also has 3 numbers of its own, always the same for that seat. These are called position numbers. They start random and are learned, like embeddings.

A letter's numbers = embedding + position numbers, added one by one. So the same letter in two seats gets different numbers: that is how the model tells near from far.

Click a seat to move “t” there. Watch which numbers change.

How does the last letter choose which of these to look at?

A question and labels

Now the last letter looks back at all 8 letters to find the ones that help. First, every letter needs something to compare.

The last letter takes its 3 numbers (its embedding + its seat's position numbers) and turns them into 3 numbers that say what it is looking for. We call them its question. They are made with 9 weights, multiplying and adding as when making a score. These are the query weights: query means question.

Every letter, the last one too, turns its 3 numbers into 3 numbers that say what it has. We call them its label. They are made the same way, with 9 other weights: the key weights.

Click a letter's label, or the question, to see how it is made.
8 labels: what each letter has1 question: what the last letter looks for

The question and the labels are ready. How well does each label fit the question?

Matches

To see how well a letter fits, take the dot product of the question and its label, then divide by 1.73. This is the letter's match. The bigger the match, the better that letter fits the question.

🤔 Why divide by 1.73?

1.73 is √3, because there are 3 numbers in each list. Dividing keeps the matches from growing too big while the model learns. Real models with 64 numbers divide by √64 = 8.

Every letter's match is a bar. Click one to see how it is worked out.

Matches are just numbers. How much should the last letter listen to each?

Who to listen to

Softmax turns the 8 matches into shares that add up to 100%, the way it turned scores into chances. The shares say how much the last letter listens to each letter. They are called the attention.

Pick 8 letters. The bars show where the last letter's attention goes.

The model learned this by itself. Nobody told it to look at “e”.

It knows where to look. What does it take from there?

Mix

Every letter also makes 3 numbers to hand over, with 9 more weights. These are its value, and the weights the value weights.

The last letter multiplies each value by its share and adds them up. The result is called the mix.

Then it adds its own numbers back, so it doesn't forget itself. Finally, 42 more weights turn these 3 numbers into the 14 scores. They are called the output weights. Softmax gives the chances, as before.

Pick 8 letters. See the mix, then the guess.

Your model has 135 numbers: 42 embedding + 24 position + 27 query, key and value + 42 output weights.

The code

Guess what each print shows. Then press ▶ Run.

import torch
import torch.nn.functional as F

text = "the cat sat on the mat. the dog sat on the log."
unique_chars = sorted(set(text))
vocab_size = len(unique_chars)
char_to_number = {}
number_to_char = {}
for number, char in enumerate(unique_chars):
    char_to_number[char] = number
    number_to_char[number] = char

# Examples: the last 8 letters, and the next one
windows = []
next_chars = []
for i in range(len(text) - 8):
    windows.append([char_to_number[c] for c in text[i:i + 8]])
    next_chars.append(char_to_number[text[i + 8]])
windows = torch.tensor(windows)
next_chars = torch.tensor(next_chars)
print("Examples:", len(next_chars))

# The model: small random numbers to start
torch.manual_seed(29)
embedding = (torch.randn((vocab_size, 3)) * 0.5).requires_grad_()   # 3 numbers per letter
position = (torch.randn((8, 3)) * 0.5).requires_grad_()             # 3 numbers per position
query = (torch.randn((3, 3)) * 0.5).requires_grad_()
key = (torch.randn((3, 3)) * 0.5).requires_grad_()
value = (torch.randn((3, 3)) * 0.5).requires_grad_()
out = (torch.randn((3, vocab_size)) * 0.5).requires_grad_()
params = [embedding, position, query, key, value, out]
print("Numbers in the model:", sum(p.numel() for p in params))

# One guess: look back, weigh, mix
def guess(win):
    x = embedding[win] + position                      # each letter's numbers, plus its position's
    q = x[:, -1] @ query                               # the last letter's question
    k = x @ key                                        # every letter's label
    v = x @ value                                      # what every letter offers
    match = (k @ q.unsqueeze(2)).squeeze(2) / 3 ** 0.5  # how well each label fits the question
    attention = F.softmax(match, dim=1)                # shares that add up to 1
    mixed = (attention.unsqueeze(2) * v).sum(dim=1)    # mix the offers by those shares
    return (mixed + x[:, -1]) @ out, attention         # scores for every next letter

# Learn: predict, measure, find directions, move
learning_rate = 0.5
for step in range(300):
    scores, attention = guess(windows)
    loss = F.cross_entropy(scores, next_chars)
    for p in params:
        p.grad = None
    loss.backward()
    for p in params:
        p.data = p.data - learning_rate * p.grad
    if step % 50 == 0:
        print("Step", step, "loss:", round(loss.item(), 3))
print("Final loss:", round(loss.item(), 3))

# Write 40 new letters, starting from "the cat "
torch.manual_seed(42)
output = "the cat "
for step in range(40):
    win = torch.tensor([[char_to_number[c] for c in output[-8:]]])
    scores, attention = guess(win)
    chances = F.softmax(scores[0], dim=0)
    picked = torch.multinomial(chances, num_samples=1).item()
    output = output + number_to_char[picked]
print(output)

🤔 What is new in this code?
  • windows holds every example's last 8 letters: a table of 39 rows × 8 numbers.
  • embedding[win] + position gives each letter its embedding plus its place's position numbers.
  • query, key and value are 3 × 3 weight tables. x @ key multiplies and adds, for every letter at once.
  • F.softmax(match, dim=1) turns each example's 8 matches into shares that add up to 1.
  • unsqueeze and squeeze only add or remove a size-1 direction so the tables line up. They don't change any number.
