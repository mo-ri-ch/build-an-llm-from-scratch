Looking further back

The problem

I can learn my own numbers now. But I still write words like “sathe”.

Lesson 4 left your model here:

  • It learns its numbers by itself, from random scores.
  • But it still sees only the last letter. After “sat”, it only sees t, and after t comes h most often. So it writes “sathe”.
  • Counting with the last 3 letters would need a table of 38,416 boxes, and almost all of them stay empty.

So the question is: can your model look at the last 3 letters without a giant table?

What if, instead of one giant table, it used small ones?

Three small tables

Your model will look at the last 3 letters. Take “cat”: the third-last letter is c, the second-last is a, the last is t.

Instead of one giant table, it uses 3 small tables, one for each of those positions. Each is 14 × 14, exactly like the table in Lesson 4:

  • The third-last table looks at the third-last letter (c in “cat”).
  • The second-last table looks at the second-last letter (a).
  • The last table looks at the last letter (t).
Click any letter in the text. It becomes the next letter to guess, and the 3 letters before it light up.

Each letter picks one row in its own table. So every guess uses 3 rows: one from each table.

Each table works like the one in Lesson 4: one letter → a score for every possible next letter. The last table is exactly that table (last letter → next). The other two do the same, but with a letter further back.

So each table only looks at 2 specific letters: its own letter and the next one. It has no place for the letters in between, so it uses the same score whatever they are. For example, the third-last table's score for c _ _ → space is used after “cat”, and would be used after “cot” or “con” too.

Three rows. How do they make one guess?

Add the rows

Step a) Predict

To guess the next letter, your model adds the 3 rows together, score by score. Then softmax turns the added scores into chances, just like in Lesson 4.

The tables start with random scores, like in Lesson 4. So for now the chances are random too.

Pick a 3-letter group. Then click any letter's column to see its addition worked out below.

Every column is added the same way. All 14 added scores then go through softmax, so the chances add up to 100%.

“cat” and “sat” use two of the same rows. Why does that matter?

Shared rows

“cat” uses row a of the second-last table and row t of the last table. So does “sat”, and so does “mat”.

So when row t of the last table learns something from “cat”, it helps “sat” and “mat” too.

Pick a table and a row. See every 3-letter group in the text that uses it.

One giant table would give each 3-letter group its own row, and those rows would learn nothing from each other. Small tables let one row help many groups. And they need far fewer numbers:

One giant table (every 3-letter group × 14 next letters)
38,416
Three small tables (3 × 14 × 14)
588

Could we fill these 588 numbers by counting, like in Lesson 3?

Why not count them?

Let's try. Fill each table by counting, like in Lesson 3. For example, the last table counts which letter comes right after the last letter. Then add the 3 rows, as your model does.

Pick a group. Does adding counted rows give the right answer?

It goes wrong. A count says how often a pair appeared. But here each row is only one part of a guess, added to two other rows. No count can tell you how big each part should be so that the sum comes out right.

That's what learning does: guess, measure the loss, and nudge all three rows together until their sum gives good chances.

Numbers like these, each used in many guesses and only one part of each, are called shared numbers. They can't be filled by counting. They have to be learned.

Learning still reads the whole text, many times, like in Lesson 4. What it saves is boxes: 588 instead of 38,416.

The code

Guess what each print shows. Then press ▶ Run.

import torch
import torch.nn.functional as F

text = "the cat sat on the mat. the dog sat on the log."
unique_chars = sorted(set(text))
vocab_size = len(unique_chars)
char_to_number = {}
number_to_char = {}
for number, char in enumerate(unique_chars):
    char_to_number[char] = number
    number_to_char[number] = char

# Groups: the last 3 letters, and the next one
third_last = []
second_last = []
last = []
next_chars = []
for i in range(len(text) - 3):
    third_last.append(char_to_number[text[i]])
    second_last.append(char_to_number[text[i + 1]])
    last.append(char_to_number[text[i + 2]])
    next_chars.append(char_to_number[text[i + 3]])
third_last = torch.tensor(third_last)
second_last = torch.tensor(second_last)
last = torch.tensor(last)
next_chars = torch.tensor(next_chars)
print("Groups:", len(next_chars))

# The model: 3 small tables of random scores
torch.manual_seed(42)
table_third_last = torch.randn((vocab_size, vocab_size), requires_grad=True)
table_second_last = torch.randn((vocab_size, vocab_size), requires_grad=True)
table_last = torch.randn((vocab_size, vocab_size), requires_grad=True)
print("Numbers in the model:", 3 * vocab_size * vocab_size)

# Learn: the same 4 steps as Lesson 4, for all 3 tables
learning_rate = 10
for step in range(300):
    scores = table_third_last[third_last] + table_second_last[second_last] + table_last[last]   # a) predict
    loss = F.cross_entropy(scores, next_chars)                        # b) measure
    table_third_last.grad = None
    table_second_last.grad = None
    table_last.grad = None
    loss.backward()                                                   # c) find directions
    table_third_last.data = table_third_last.data - learning_rate * table_third_last.grad            # d) move
    table_second_last.data = table_second_last.data - learning_rate * table_second_last.grad
    table_last.data = table_last.data - learning_rate * table_last.grad
    if step % 50 == 0:
        print("Step", step, "loss:", round(loss.item(), 3))

# Write 40 new letters, starting from "the"
torch.manual_seed(42)
output = "the"
for step in range(40):
    scores = table_third_last[char_to_number[output[-3]]] + table_second_last[char_to_number[output[-2]]] + table_last[char_to_number[output[-1]]]
    chances = F.softmax(scores, dim=0)
    picked = torch.multinomial(chances, num_samples=1).item()
    output = output + number_to_char[picked]
print(output)

🤔 What is new compared with Lesson 4?
  • Each group has 3 letters, so there are 3 lists: third_last, second_last, last.
  • 3 tables instead of 1, and scores adds one row from each.
  • Every step moves all 3 tables. loss.backward() finds the gradients for all 588 numbers at once.
  • output[-1] is the last letter written so far, output[-2] the second-last, output[-3] the third-last.
